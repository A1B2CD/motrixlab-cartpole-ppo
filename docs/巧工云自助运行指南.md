# 巧工云自助运行指南

这份文档是给「自己上云跑一遍」用的，和 `README.md` 第 3 节互补：README 讲的是项目本身，这里讲的是**从拿到一台空机器到把证据推回 GitHub 的完整操作**。

预计总耗时：**20–40 分钟**（其中装依赖 3–8 分钟，训练 1–3 分钟）。

---

## 0. 上机前先填这张表

拿到实例后，先把这四项抄下来，后面每条命令都要用：

```text
公网 IP        : ______________________
SSH 端口       : ______________________   （默认 22，很多平台会改成 3xxxx）
用户名         : ______________________   （常见 root / ubuntu）
认证方式       : 密钥文件 ______________________  或  密码
```

> 巧工云控制台里一般在「实例详情 → 连接信息」或「SSH 登录」处。如果只给了 Web 终端（网页里的黑框），也能用，只是没法建 SSH 隧道看 TensorBoard，这时改用 `scripts/04_export_scalars.sh` 在服务器端出曲线图。

Windows 10/11 自带 OpenSSH 客户端，直接开 PowerShell 就能连，不需要装 PuTTY：

```powershell
ssh -i C:\path\to\key.pem ubuntu@<公网IP> -p <SSH端口>
```

## 1. 上机后 60 秒自检

```bash
# 1) 是不是真的 GPU 机器
nvidia-smi

# 2) 系统版本（需要 Ubuntu 20.04 / 22.04，能 sudo）
cat /etc/os-release | head -3
sudo -n true && echo "sudo OK" || echo "需要密码或没有 sudo"

# 3) 磁盘（torch + 依赖约 3 GB，加上 checkpoint 很小）
df -h ~

# 4) 能不能访问 GitHub（决定用哪种拉代码方式）
curl -sS -o /dev/null -w "github.com %{http_code}\n" --max-time 15 https://github.com
curl -sS -o /dev/null -w "tuna      %{http_code}\n" --max-time 15 https://pypi.tuna.tsinghua.edu.cn/simple
```

判断标准：

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| `github.com 200` | 能直连 | 用第 2 节的**方式 A** |
| `github.com 000` 超时 | 拉不到代码 | 用**方式 C / D**（本机打包传上去） |
| `tuna 200` | 依赖能装 | 正常跑 `01_bootstrap.sh` |

`nvidia-smi` 右上角的 `CUDA Version` 很重要：

- **≥ 12.8**（驱动 ≥ 570）→ `01_bootstrap.sh` 自动装 `torch 2.7.0+cu128`
- **< 12.8** → 自动装 CPU 版。**这不是错误**，CartPole 用 CPU 一样跑（本地就是 CPU 版）

## 2. 把代码弄到服务器上（三种方式，按连通性选）

### 方式 A：服务器能直连 GitHub（最省事）

```bash
git clone https://github.com/A1B2CD/motrixlab-cartpole-ppo.git
cd motrixlab-cartpole-ppo
```

### 方式 B：用镜像加速（直连慢但没完全断）

镜像站经常变，能用就用，不能用就跳到方式 C：

```bash
git clone https://ghfast.top/https://github.com/A1B2CD/motrixlab-cartpole-ppo.git
```

### 方式 C：本机打 git bundle（推荐兜底，保留提交历史）

在**你自己的 Windows** 上执行：

```powershell
cd D:\robot\rl_sim\motrixlab-cartpole-ppo
git bundle create ..\cartpole.bundle --all
scp -P <SSH端口> ..\cartpole.bundle <用户名>@<公网IP>:~/
```

回到服务器：

```bash
git clone ~/cartpole.bundle motrixlab-cartpole-ppo
cd motrixlab-cartpole-ppo
git remote set-url origin https://github.com/A1B2CD/motrixlab-cartpole-ppo.git
```

### 方式 D：直接传目录（最粗暴，丢掉提交历史）

```powershell
cd D:\robot\rl_sim
tar -czf cartpole.tar.gz motrixlab-cartpole-ppo
scp -P <SSH端口> cartpole.tar.gz <用户名>@<公网IP>:~/
```

```bash
tar -xzf ~/cartpole.tar.gz && cd motrixlab-cartpole-ppo
```

## 3. 一键跑完三项证据

```bash
bash scripts/run_all.sh
```

它按顺序做这些事：

| 步骤 | 产出 |
| --- | --- |
| `01_bootstrap.sh` | 系统依赖 + uv + Python 3.10 + `uv sync` |
| `00_check_server.sh` | `evidence/cloud/00_server_report.txt/.json`（硬件 + 软件版本） |
| `02_train.sh` | `motrixlab/runs/cartpole/<时间戳>_PPO/`（11 个 checkpoint + tfevents） |
| `04_export_scalars.sh` | `04_scalars.csv`、3 张曲线 PNG、`04_summary.md` |
| `03_tensorboard.sh` | 启动 TensorBoard，**停在这里等你截图** |
| `05_play_headless.sh` | `05_play_headless.log`（推理步数与平均回报） |
| `06_play_xvfb.sh` | `06_play_xvfb.png`（虚拟显示截图，失败不影响证据） |
| `03_tensorboard_stop.sh` | 截图完按回车后停掉 TensorBoard |
| `07_collect_evidence.sh` | 目录树 + sha256 + 清单 |
| `compare_runs.py` | `evidence/comparison.md`（本地 vs 云端对比表） |

中途它会**停下来等你截图**（第 4 节）。如果只想先把训练跑完，用：

```bash
SKIP_TB=1 bash scripts/run_all.sh
```

> `01_bootstrap.sh` 会改写 `motrixlab/pyproject.toml` 和 `motrixlab_rl/pyproject.toml` 里的 PyTorch 索引，这是**预期行为**，`08_push_evidence.sh` 会把改动一起提交。

## 4. 看 TensorBoard（不要在服务器上开浏览器）

TensorBoard 默认只监听 `127.0.0.1:6006`。在**你自己的 Windows** 上开一个 PowerShell 窗口：

```powershell
ssh -N -L 6006:127.0.0.1:6006 <用户名>@<公网IP> -p <SSH端口>
```

这个窗口会一直挂着（没有任何输出，正常）。然后浏览器打开：

```text
http://127.0.0.1:6006
```

进 **SCALARS** 页签 → 展开 `Reward` 和 `Loss` → 截图保存为：

```text
evidence/cloud/03_tensorboard_reward_loss.png
```

**没有 Web 终端 / 建不了隧道怎么办？** 跳过截图，用服务器端导出的曲线：

```bash
bash scripts/04_export_scalars.sh
# 产出 evidence/cloud/04_reward_and_loss.png，内容和 TensorBoard 曲线一致
```

把这张图当第 2 项证据同样成立（它直接读的就是 tfevents）。

## 5. 把证据推回 GitHub

服务器上没有你的浏览器登录态，二选一。

### 方案 1：Deploy key（推荐，长期可用）

```bash
ssh-keygen -t ed25519 -C "qiaogong-server" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

复制输出的整行，到 GitHub 仓库页面：

```text
Settings → Deploy keys → Add deploy key
```

**必须勾选 `Allow write access`**，然后：

```bash
ssh -T git@github.com          # 看到 "Hi ... You've successfully authenticated" 即可
bash scripts/08_push_evidence.sh
```

### 方案 2：PAT over HTTPS（临时用）

在 GitHub → Settings → Developer settings → Personal access tokens 建一个带 `repo` 权限的 token：

```bash
export GH_TOKEN=ghp_xxxxxxxx
git remote set-url origin https://x-access-token:${GH_TOKEN}@github.com/A1B2CD/motrixlab-cartpole-ppo.git
bash scripts/08_push_evidence.sh
```

### 方案 3：推不上去就传回本机（最保险）

```bash
# 服务器上：打包证据
tar -czf evidence-cloud.tar.gz evidence/cloud evidence/comparison.md motrixlab/runs
```

```powershell
# 本机：拉回来，再本地推送
scp -P <SSH端口> <用户名>@<公网IP>:~/motrixlab-cartpole-ppo/evidence-cloud.tar.gz .
tar -xzf evidence-cloud.tar.gz -C D:\robot\rl_sim\motrixlab-cartpole-ppo
cd D:\robot\rl_sim\motrixlab-cartpole-ppo
git add -A
git commit -m "evidence: CartPole PPO 云端运行证据"
git push
```

> 本机推送需要代理：`git config http.proxy http://127.0.0.1:7897`（这个仓库已配好）。

## 6. 跑完对比

`run_all.sh` 最后会自动生成 `evidence/comparison.md`。也可以单独跑：

```bash
bash scripts/09_compare.sh
```

它会读两边的证据文件，输出一张「本地 Windows vs 巧工云」的对照表：

- 硬件：CPU 型号/核数、内存、GPU、驱动、CUDA 可用性
- 软件：Python、torch、motrixsim、skrl、numpy、gymnasium
- 训练：训练目录、checkpoint 数、episode 数、首末平均回报、首末 value loss、**训练耗时**
- 推理：加载的 checkpoint、步数、平均回报
- 自动结论：是否都收敛、谁更快、GPU 有没有实际帮助

任意一侧缺文件不会报错，缺的显示「待生成」。

## 7. 常见报错对照表

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `bad interpreter: /usr/bin/env bash^M` | 脚本被 CRLF 污染 | 仓库已用 `.gitattributes` 强制 LF；若手工改过：`sed -i 's/\r$//' scripts/*.sh` |
| `ModuleNotFoundError: No module named 'motrix_rl'` | 工程放在**中文路径**下，editable `.pth` 解析失败 | 换到纯 ASCII 路径，如 `~/motrixlab-cartpole-ppo` |
| `uv sync` 卡在 `Resolving` | 网络问题 | 仓库已配清华 tuna 源；仍不行时检查第 1 节的 tuna 连通性 |
| `torch.cuda.is_available() == False` | 驱动 < CUDA 12.8，装了 CPU 版 | 正常现象，CartPole 不需要 GPU；要 GPU 版见 `TORCH_VARIANT=cu128` |
| `failed to load an image` | 缺贴图资产 | 仓库只保留 CartPole 需要的 `motphys-ground.png`；其他环境缺资产属预期 |
| `TensorBoard: command not found` | 没在项目 venv 里跑 | 用 `uv run tensorboard ...`，不要直接 `tensorboard` |
| `GH008 ... unknown Git LFS objects` | 提交里混入了 LFS 指针 | 本仓库已删除全部指针；不要从上游 zip 再拷 LFS 文件进来 |
| `06_play_xvfb.sh` 截图失败 | 云上没有 Vulkan/llvmpipe | 属正常，headless 证据（第 3 项）仍然有效 |
| `permission denied (publickey)` | 密钥没配对或没加 deploy key | 检查 `ssh -T git@github.com`，或改用 PAT |
