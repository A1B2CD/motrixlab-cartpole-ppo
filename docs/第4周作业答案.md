### 3. 观测编码与欠驱动（4 分）

#### 3.1 角度从 π 跨到 −π：直接角度 vs sin/cos（2 分）

取跨越前后的两个状态：`θ₁ = +179°`、`θ₂ = −179°`（物理上只差 **2°**）。

| 编码方式 | θ = +179° | θ = −179° | 两者数值差 | 是否连续 |
| --- | --- | --- | --- | --- |
| **直接输入角度（rad）** | `+3.12414` | `−3.12414` | **6.24827 rad ≈ 358°** | ❌ 在 ±π 处跳变 2π |
| **sin/cos 编码** | `(cos, sin) = (−0.999848, +0.017452)` | `(cos, sin) = (−0.999848, −0.017452)` | **0.03491**（二维欧氏距离），对应圆心角 2° | ✅ 连续 |

计算过程：

```text
cos(179°)  = −0.9998477      sin(179°)  = +0.0174524
cos(−179°) = −0.9998477      sin(−179°) = −0.0174524

直接角度：|3.12414 − (−3.12414)| = 6.24827 rad   ← 网络看到"差了 358°"
sin/cos ：√[(0−0)² + (0.0174524−(−0.0174524))²] = 0.0349048   ← 只差 2°
```

**结论：**

- 直接输入角度时，网络必须自己学会"±π 是同一个方向"，而这在数值上是最大跳变（6.28 rad），
  在 π 附近做插值/求导都会失真，策略容易在"竖直向下"附近抖。
- 用 `(cosθ, sinθ)` 把角度映射到单位圆上，±π 处两个分量都连续，
  网络只需做线性组合就能恢复方向信息，也不存在"绕圈"的歧义。
- 这就是 Pendulum（`pendulum_np.py:67`）和 Acrobot（`acrobot_np.py:75-84`）都用
  `cos/sin` 而 CartPole（`cartpole_np.py:59`）直接用角度的原因：
  CartPole 的 θ 只在 `|θ|≤0.2 rad` 附近有意义，永远到不了 ±π，不存在跨越问题。

#### 3.2 Acrobot 的关节数与欠驱动（2 分）

```text
关节数：2 个（shoulder 肩、elbow 肘），见 acrobot.xml:35、39
动作维数：1 维，见 acrobot_np.py:33  gym.spaces.Box(-1.0, 1.0, (1,), ...)
直接受驱动的关节：只有 elbow（肘），见 acrobot.xml:46-48
```

```xml
<!-- motrix_envs/src/motrix_envs/basic/acrobot/acrobot.xml:46-48 -->
<actuator>
  <motor name="elbow" joint="elbow" gear="30" ctrllimited="true" ctrlrange="-1 1"/>
</actuator>
```

**结论：** 两个关节、一维动作，`<actuator>` 里只有 `elbow` 一个 motor，
`shoulder` 完全没有执行器 → **肩关节欠驱动**。

物理上只能通过"甩动小臂"产生的反作用力矩把整条手臂摆起来（类似人荡秋千），
控制器无法直接给肩关节施加力矩。这正是 Acrobot 比 Pendulum 难的原因：
Pendulum 的唯一关节直接受驱动，Acrobot 要把 1 维力矩"传递"到 2 个自由度上。

> 对比：CartPole 也是 2 关节 1 电机（`slider` 有电机、`hinge` 没有），
> 但它是**串联的直线+旋转**，欠驱动程度比 Acrobot 的双旋转轻得多。

### 5. 分析（8 分）

#### 5.1 两组在到达直立范围和末帧姿态上的差异（3 分）

**结论先说：两组「能不能直立」没有差异，差异在「多快进入」和「保持多久」。**

| 对比项 | A 组（能量项保留） | B 组（能量项系数 0） |
| --- | --- | --- |
| 曾进入 ≤15° 的回合数 | 3 / 3 | 3 / 3 |
| 末帧在 ≤15° 的回合数 | 3 / 3 | 3 / 3 |
| **首次进入直立的步数**（seed 0/1/2） | **5 / 11 / 8**，均值 **8.0** | **7 / 24 / 15**，均值 **15.3** |
| **直立占比**（三回合均值） | **98.2%** | **96.4%** |
| 末帧角度 | 全部 **+1.3°** | 全部 **−1.3°** |
| 累计奖励（三回合均值） | **1239.32**（99.95% 上限） | **1237.86**（99.83% 上限） |

逐项解读：

1. **到达能力：完全相同。** 六个回合全部进入过直立范围，末帧也全部仍在范围内。
   这说明能量项**不决定策略能否学会直立**——与 §5.2 的数值分析一致（主项最优 3.10 远大于能量项最优 1.00）。
2. **进入速度：A 快约一倍。** 三个种子上 A 分别用 5 / 11 / 8 步进入，B 用 7 / 24 / 15 步。
   seed 1（初始 −29.9°，偏离最大）差距最明显：A 用 11 步，B 用 24 步。
3. **保持程度：A 略好。** 直立占比 98.2% vs 96.4%，差 1.8 个百分点。
4. **末帧姿态：都在范围内，符号不同**（+1.3° vs −1.3°），都远小于 15° 阈值，不构成实质差异。
5. **训练曲线方向一致**：末段均值 A **1182.41** > B **1117.97**（+64.4，+5.8%），
   首值 A **+85.34** vs B **−188.26**（B 前期平均回报为负）。

> 差值只有 1.5 分（0.12%），且两组各只训一次，**不能**据此断言 A 一定更好；
> 但「A 更快进入直立 + 直立占比更高 + 训练首值不为负」三点方向一致，说明能量项在这里起的是
> **加速收敛的塑形作用**，而不是把策略拉向错误姿态。

#### 5.2 能量奖励可能怎样影响了这些现象（3 分）

先看这一项在数值上到底奖励什么（这是本题的关键，容易被名字误导）：

```text
energy = 0.5·θ̇² + (1 − cosθ)
  θ = 0   （摆杆竖直向上，见 pendulum.xml:26 摆杆 fromto 0 0 0 → 0 0 0.5）→ energy = 0
  θ = π   （摆杆垂下、静止）                                            → energy = 2

energy_target = 2.0，margin = 2.0，gaussian，value_at_margin = 0.1
  energy = 2.0（垂下静止）→ energy_reward = 1.00
  energy = 1.0            → energy_reward ≈ 0.56
  energy = 0.0（竖直静止）→ energy_reward = 0.10
```

也就是说，**这一项实际奖励的是"摆到下方静止"**（公式沿用 dm_control 里
"0 = 下垂"的角度约定，而本模型的 0 是竖直向上）。

对总奖励的影响：

| 状态 | `3.0·upright` | `energy_reward` | 合计（忽略小惩罚项） |
| --- | --- | --- | --- |
| 竖直向上静止 | 3.0 | 0.10 | **3.10** |
| 垂下静止 | 0.0 | 1.00 | **1.00** |

所以能量项**没有改变最优解**（仍然是竖直向上），它的作用只能落在**收敛过程**上。
从代码看它有三个可检验的副作用：

1. **方向与主项相反**：它把摆杆往「E = 2.0，即垂下静止」拉（1.00/步），
   而主项把摆杆往竖直拉（3.00/步）。因为 3.10 > 1.00，最优解不变，
   但梯度里确实多了一个"往下"的分量。
2. **稠密、平滑、有界**：`tolerance(..., gaussian)` 在任意姿态都给出 0.1～1.0 之间的值，
   不像 `upright` 只在竖直附近才有梯度。这等价于给回报加了一个平滑 baseline，
   缓解训练初期回报被 `0.2ω²` 速度惩罚主导的问题——B 组首值 −188.26、A 组首值 +85.34 正是这一点的直接证据。
3. **惩罚高速摆动**：`0.5θ̇²` 使摆动越快 E 越偏离 2.0，奖励越小；而摆起本身需要快速摆动。
   这是唯一一个"预测 A 更差"的机制。

**实测支持哪一边？** 第 2 点的收益压过了第 3 点的副作用：
A 组不仅首值不为负，收敛后还略好（末段均值 +5.8%、直立占比 +1.8 pp、进入直立快一倍）。
第 1 点预测的"策略停留在下方"在回放里**没有出现**——六条回放的直立占比都在 94% 以上。

**实测（A 组 seed 0）**：初始 `+17.6°`，第 **5** 步进入直立范围，全程 **99.0%** 的时间在 ≤15° 内，
末帧 `+1.3°`，累计奖励 **1239.17** → 平均 **3.098/步**，基本等于理论上限 **3.10**
（`3.0·upright + energy_reward` 在"竖直静止"时 = 3.0 + 0.1）。
说明在本次训练预算下（5000 步 × 2048 环境 = 1024 万环境步），
能量项**没有**阻止策略收敛到全局最优。

因此更准确的表述是：能量项是一个"方向相反但权重较小"的塑形项——
它**不改变最优解**，只影响**收敛过程**（摆起快慢、保持程度）。
实测两组差异正好落在"进入直立的时刻 / 直立占比"上，而不是"最后能不能直立"：
A 首次进入 5/11/8 步、直立占比 98.2%；B 首次进入 7/24/15 步、直立占比 96.4%。
（作业也明确说明不要求 B 组更好，两组奖励定义不同，不能比总奖励大小。）

#### 5.3 这次实验的局限（至少两点，2 分）

1. **单种子、单次训练**：两组都只用了默认 `seed=42` 训练一次，没有多种子重复，
   观测到的差异可能来自训练随机性而非能量项本身。
2. **样本量小**：每组只回放 3 个回合（seed 0/1/2），且判据只有 15° 一个阈值，
   没有统计"停留时长""角速度"等指标。
3. **末帧不能代表整回合**：末帧在直立范围内，不代表整回合都稳定（可能只是恰好停在那一刻）。
4. **奖励定义不同，总奖励不可比**：两组的奖励函数不同，不能用累计奖励大小判断优劣。
5. **只做了 0/1 两点对照**：没有扫中间系数（0.25 / 0.5），无法判断是"线性影响"还是"阈值效应"。
6. **角度约定的解释依赖代码阅读**：若模型的角度零点与本文推断不一致，
   §5.2 的"能量项奖励下方"结论需要修正（可用回放画面交叉验证：
   `|θ|` 小的帧里摆杆应指向正上方）。

#### 2.1 观测构造（截图 `reacher_np.py:64-69`）

#### 2.3 奖励计算（截图 `reacher_np.py:74-78`）

```python
74:         finger_xy = self._finger.get_pose(data)[:, :2]
75:         dist = np.linalg.norm(self._target_xyz[:, :2] - finger_xy, axis=-1)
76:         rwd = reward.tolerance(

78:         )
```

**解释：** 奖励只由末端到目标的距离 `dist` 决定（`target_size = 0.02`，`reacher/cfg.py:34`）：

| `dist` | 奖励 |
| --- | --- |
| `≤ 0.02 m` | **1.0**（满分区，`bounds=(0, 0.02)` 内直接取 1） |
| `0.02 ~ 0.04 m` | `1 − (dist − 0.02)/0.02`，从 1 线性降到 0 |

### 3. 思考题（10 分）

> **目标点每个回合都会变化。如果观测中不包含任何目标位置信息（包括末端到目标的相对位置），
> 策略还能可靠地到达目标吗？**

#### 3.1 判断（2 分）

**不能。** 策略无法可靠到达目标，最多只能学会一个与目标无关的固定行为（例如把手臂伸向某个平均位置）。

#### 3.2 原因（4 分）

1. **问题变成部分可观测 MDP（POMDP）**：目标每回合从 `U(-0.15,0.15)×{0.15}` 独立采样，
   而观测里没有任何目标线索。于是**同一个观测会对应无数个不同的目标**，
   策略对同一输入只能输出同一个动作，无法区分"这次目标在左还是在右"。
2. **最优策略退化为"目标无关"**：在期望意义下，最优动作是让末端停在目标的**分布中心**
   （本例约 `(0, 0.15)`）附近，这对任何具体目标都不是"到达"，只是"平均意义上最近"。
   对 `|target_x| = 0.15` 的回合，误差会达到 0.15 m，远超 0.02 m 的满分区。
3. **奖励不可优化到高分**：`dist ≤ 0.02` 才给 1 分，而目标在 x 方向跨度 0.3 m，
   一个固定姿态最多只能在极少数目标上碰巧命中，期望奖励接近 0。
4. **信息论角度**：策略的输出 `a = π(o)` 与目标 `g` 条件独立（`o ⫫ g`），
   所以 `I(a; g) = 0`，不可能实现"按目标调整动作"。

#### 3.3 代码依据：要删掉哪些分量（4 分）

当前观测 10 维（`reacher_np.py:69`：`concat([qpos, to_target, qvel])`），逐维检查：

| 下标 | 内容 | 是否含目标信息 | 处理 |
| --- | --- | --- | --- |
| `obs[0]` | `θ_shoulder` | ❌ 不含 | **保留** |
| `obs[1]` | `θ_wrist` | ❌ 不含 | **保留** |
| `obs[2]` | `target_x` | ✅ **目标坐标本身** | **必须删除** |
| `obs[3]` | `target_y` | ✅ **目标坐标本身** | **必须删除** |
| `obs[4]` | `to_target_x` | ✅ 目标−末端 | **必须删除** |
| `obs[5]` | `to_target_y` | ✅ 目标−末端 | **必须删除** |
| `obs[6]` | `θ̇_shoulder` | ❌ 不含 | **保留** |
| `obs[7]` | `θ̇_wrist` | ❌ 不含 | **保留** |
| `obs[8]` | `ẋ_target` | ✅ 目标状态（恒 0） | **必须删除** |
| `obs[9]` | `ẏ_target` | ✅ 目标状态（恒 0） | **必须删除** |

**结论：** 需要删除 `obs[2]`、`obs[3]`（`qpos` 里的目标两个 slide 关节）、
`obs[4]`、`obs[5]`（`to_target` 两项）、`obs[8]`、`obs[9]`（`qvel` 里的目标速度两项），
一共 **6 维**，剩下的 4 维

```text
obs_clean = [θ_shoulder, θ_wrist, θ̇_shoulder, θ̇_wrist]
```

才**完全不含目标信息**。对应代码修改（示意）：

```python
# reacher_np.py:69 改成
obs = np.concatenate([qpos[:, :2], qvel[:, :2]], axis=-1)   # 4 维
```

> 补充：`obs[8]`、`obs[9]` 在本环境里恒为 0（`reset()` 只设 `set_dof_pos`，目标速度没被激励），
> 形式上不含信息，但为了严格满足"完全不含目标信息"，仍应删掉——
> 否则一旦以后给目标加了速度，就会泄漏目标状态。
