### 3.4 配置国内镜像（本次网络环境必须）

本次实测：`pypi.org` 与 `files.pythonhosted.org` 超时，`pypi.tuna.tsinghua.edu.cn` 正常；`download.pytorch.org` 正常；`github.com` 被重置，但 `codeload.github.com`、`raw.githubusercontent.com`、`api.github.com` 可用。

在 `MotrixLab-0.3.0/pyproject.toml` 末尾加入：

```toml
[[tool.uv.index]]
name = "tuna"
url = "https://pypi.tuna.tsinghua.edu.cn/simple"

[[tool.uv.index]]
name = "pytorch-cpu"
url = "https://download.pytorch.org/whl/cpu"
```

> 注意：`tool.uv.sources` 里引用的 index 必须定义在**项目根 `pyproject.toml` 的 `[[tool.uv.index]]`** 中；只写在 `uv.toml` 会报 `Package torch references an undeclared index`。

### 3.5 关键适配：把 cu128 换成 CPU 版 PyTorch

MotrixLab v0.3.0 默认锁的是 `torch==2.7.0+cu128`，但本机驱动 528.79 最高只支持 CUDA 12.0，且 GTX 1050 Ti 是 Pascal（sm_61），cu128 轮子无法使用。CartPole 是 4 维观测、1 维动作、32×32 小网络，**CPU 完全够用**，因此改成 CPU 轮子。

修改 `motrix_rl/pyproject.toml`：

```toml
[project.optional-dependencies]
skrl-torch = [
    "skrl===1.4.3",
    "torch===2.7.0+cpu",
]
rslrl = [
    "rsl-rl-lib>=4.0.0",
    "torch===2.7.0+cpu",
    "torchvision===0.22.0+cpu",
    "torchaudio===2.7.0+cpu",
]

[tool.uv.sources]
motrix-envs = { workspace = true }
torch = { index = "pytorch-cpu" }
```

同时把 `motrix_envs/pyproject.toml` 的 `motrixsim>=0.7.0` 固定为 `motrixsim==0.7.0`，避免重新解析时升到不兼容的新版本。

安装：

```powershell
cd D:\robot\rl_sim\MotrixLab-0.3.0
uv sync --all-packages --extra skrl-torch `
  --python C:\Users\<你>\AppData\Local\Programs\Python\Python310\python.exe
```

验证：

```powershell
uv run --no-sync python -c "import torch, motrixsim, skrl; print(torch.__version__, torch.cuda.is_available())"
# 期望：2.7.0+cpu False
```

> 如果是在有 CUDA 12.8+ 驱动的云服务器上，**不要**做这一步，直接用原始 cu128 配置即可获得 GPU 加速。

## 4. 训练闭环

### 4.1 启动训练

```powershell
uv run scripts/train.py --env cartpole --num-envs 64
```

说明：

- `--env cartpole`：环境名，必须和注册名一致；
- `--num-envs 64`：并行环境数。默认是 2048，本机 CPU 用 64 更稳、更快；
- 不指定 `--train-backend` 时自动选择：有 GPU 用 JAX/GPU，否则用 PyTorch（本次 `DeviceSupports(torch=True, torch_gpu=False)`）。

### 4.2 这行命令背后发生了什么

```text
CLI 解析（absl.flags）
  → 读取 RL 配置（motrix_rl.registry.default_rl_cfg("cartpole", "skrl", "torch")）
  → 环境创建（motrix_envs.registry.make("cartpole", sim_backend="np", num_envs=64)）
  → SKRL 包装（wrap_env → SkrlNpWrapper）
  → 构建 Policy / Value 网络（32×32 MLP）
  → 构建 PPO Agent（rollouts=32, learning_epochs=5, mini_batches=4）
  → SequentialTrainer.train()
  → 写 runs/cartpole/<时间戳>_PPO/{events.out.tfevents.*, checkpoints/*.pt}
```

对应源码：

| 环节 | 文件 |
| --- | --- |
| CLI 参数 | `scripts/train.py` |
| RL 配置注册 | `motrix_rl/src/motrix_rl/registry.py`、`motrix_rl/src/motrix_rl/tasks/cartpole.py` |
| 环境注册 | `motrix_envs/src/motrix_envs/basic/cartpole/cfg.py`、`cartpole_np.py` |
| SKRL 训练器 | `motrix_rl/src/motrix_rl/skrl/torch/train/ppo.py` |
| 日志目录 | `motrix_rl/src/motrix_rl/skrl/__init__.py` |

### 4.3 CartPole 环境关键参数

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `model_file` | `cartpole.xml` | MuJoCo 格式场景文件 |
| `sim_dt` | 0.01 s | 物理步长（XML 里也是 0.01，RK4 积分） |
| `ctrl_dt` | 0.01 s | 控制步长 |
| `max_episode_seconds` | 10 s | 单回合上限 → `max_episode_steps = 1000` |
| `reset_noise_scale` | 0.01 | 重置位置/速度噪声 |
| `render_spacing` | 2.0 | 多环境渲染间距 |
| 观测 | 4 维 | `[cart_pos, pole_angle, cart_vel, pole_vel]` |
| 动作 | 1 维，`Box(-3, 3)` | 小车推力 |
| 奖励 | 每步 +1 | 存活即得分 |
| 终止 | `|angle| > 0.2 rad` 或 `|cart_pos| > 0.8` | 倒杆/出界 |

### 6.3 为了让作业命令原样可跑，做了两处小改动

1. **`play.py` 允许只给 `--policy`**：v0.3.0 原版要求同时给 `--rllib skrl`，否则直接报错退出。现在会根据 checkpoint 后缀自动推断（`.pickle` → JAX/SKRL，`.pt` → Torch/SKRL，路径含 `rslrl` → RSLRL）。
2. **`Trainer.play()` 增加 `PLAY_MAX_STEPS` 环境变量**：默认仍然无限循环（正常演示）；设置 `PLAY_MAX_STEPS=180` 时跑完 180 步自动退出，方便自动化取证。

> 这两处改动只影响演示/取证，不改变训练算法和 checkpoint 格式。

### 6.4 关于渲染

- `play.py` 默认 `enable_render=True`，会弹出 MotrixSim/Bevy 窗口；
- 本次日志里有一条 `motphys-ground.png` 贴图加载警告，不影响物理仿真和策略加载（地面贴图格式问题，属于上游资源小瑕疵）；
- 如果云服务器没有图形界面，需要把 `play.py` 的 `enable_render` 改为 `False`，或在有 X11/虚拟显示的环境运行。

## 7. 服务器硬件配置分析

### 7.1 本次实际运行节点

| 维度 | 实测值 | 对训练的影响 |
| --- | --- | --- |
| CPU | i5-8300H，4C/8T | CartPole 的 `np` 后端主要吃 CPU；64 环境约 60 it/s，5000 步 83 秒 |
| 内存 | 15.9 GB | 64 环境 + PyTorch CPU 占用很小，余量充足 |
| GPU | GTX 1050 Ti 4 GB，CC 6.1 | 本次**未使用**；4 GB 显存也不适合上千环境的大场景 |
| 驱动 | 528.79，最高 CUDA 12.0 | 无法运行 cu128 轮子（需要 ≥570 驱动），故用 CPU 版 torch |
| 磁盘 | D: 14 GB 空闲 | venv + 缓存约 1.5 GB；大任务建议放 F: 或云盘 |
| 系统 | Windows 10 19045 | 可跑通；云平台通常用 Ubuntu 22.04 更省心 |

**结论**：这台机器适合“入门闭环 + CartPole/倒立摆”级别的任务；不适合 Go2 行走、复杂地形、几千并行环境。后者必须上云 GPU。

### 7.2 为什么 CartPole 用 CPU 就够

- 观测 4 维、动作 1 维，策略网络只有 `32×32`；
- `motrixsim` 的 `np` 后端是向量化 NumPy 物理仿真，CartPole 刚体数极少；
- PPO 每次更新只跑 5 个 epoch、4 个 mini-batch；
- 真正的瓶颈是 Python/NumPy 单步循环，而不是矩阵乘法，GPU 反而可能因为数据传输更慢。

### 7.3 云 GPU 规格建议

| 任务 | 建议配置 | 说明 |
| --- | --- | --- |
| CartPole / 倒立摆 | 4C8G，无 GPU 也可 | 本次配置即可 |
| Go2 平地行走 | RTX 4090 24 GB / A10 24 GB，16C32G | 1024～4096 环境，需要 CUDA 12.x |
| 复杂地形 / 多任务 | A100 40 GB / L40S 48 GB，32C64G+ | 显存和 CPU 并行都吃紧 |
| 驱动要求 | ≥ 570（cu128）或 ≥ 525（cu12x 兼容） | 上云前先 `nvidia-smi` 确认 |

## 8. 软件架构分析

### 8.1 四层架构

| 层 | 职责 | 本讲对应文件 |
| --- | --- | --- |
| 用户接口层 | 命令行参数、启动训练/演示 | `scripts/train.py`、`scripts/play.py`、`scripts/view.py` |
| 训练算法层 | RL 配置、PPO、checkpoint、日志 | `motrix_rl/`（`registry.py`、`skrl/torch/train/ppo.py`、`tasks/cartpole.py`） |
| 环境实现层 | 观测/动作/奖励/终止、环境注册 | `motrix_envs/`（`basic/cartpole/cfg.py`、`cartpole_np.py`） |
| 物理仿真层 | 刚体动力学、碰撞、渲染 | `motrixsim`（`np` 后端 / MotrixSim 引擎） |

### 8.2 两套注册表

```text
motrix_envs.registry
  @registry.envcfg("cartpole")  → CartPoleEnvCfg
  @registry.env("cartpole","np")→ CartPoleEnv
  registry.make("cartpole", sim_backend="np", num_envs=64)

motrix_rl.registry
  @rlcfg("cartpole")            → CartPoleSkrlPpo / CartPoleRslrlPpo
  default_rl_cfg("cartpole","skrl","torch")
```

环境名 `cartpole` 在三处必须一致：`@envcfg`、`@env`、`@rlcfg`。这也是第 6 讲代码题的红线。

### 8.3 EnvCfg 与 RLCfg 的分工

| | EnvCfg | RLCfg |
| --- | --- | --- |
| 管什么 | 仿真/任务侧 | 训练/算法侧 |
| 典型字段 | `model_file`、`sim_dt`、`ctrl_dt`、`max_episode_seconds`、`reset_noise_scale` | `num_envs`、`rollouts`、`learning_rate`、`ratio_clip`、`timesteps` |
| 好处 | 同一环境可换算法 | 同一算法可服务多环境；实验可复现、可对比 |

### 8.4 日志与 checkpoint 流水线

```text
SequentialTrainer
  → PPO.record_transition() 记录 reward / loss
  → SKRL ExperimentWriter 写 events.out.tfevents.*
  → 每 500 timesteps 写 checkpoints/agent_<step>.pt
  → 训练结束保留 best_agent.pt
  → play.py: agent.load(policy) → act → env.step → render
```

### 8.5 本讲最关键的调用链（对应作业第 1 题）

```text
CLI 解析
  → RL 配置加载
  → 环境创建
  → SKRL 包装
  → Agent 构建
  → Trainer 执行
```

顺序不能颠倒：没有环境就拿不到 observation/action space，没拿到 space 就建不了 Policy/Value 网络，没网络就无法构建 Agent。

## 9. 踩坑与排错记录

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `git clone` 卡住/超时 | `github.com` 连接被重置 | 用 `codeload.github.com` 下 zip；或 `raw.githubusercontent.com` 拉单文件 |
