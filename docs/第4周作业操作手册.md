### 2.4 Acrobot 太慢怎么办

Acrobot 默认 `timesteps=29000`、`num_envs=2048`，合计约 5940 万环境步（1–3 h）。
`25_train_all.sh` 默认降到 **512**，总步数 1485 万，实测 **417 s / 71.17 it/s** 收敛。
算力更紧张时：

```bash
# 再降并行环境数（512 → 256，约 3.5 min）
ACROBOT_ENVS=256 bash scripts/25_train_all.sh

# 只跑 Acrobot，或只跑 A/B
SKIP_AB=1 bash scripts/25_train_all.sh
SKIP_ACROBOT=1 bash scripts/25_train_all.sh

# 已存在也强制重训
FORCE=1 bash scripts/25_train_all.sh
```

作业允许提前停止训练，**在文档里写清实际步数即可**（日志里 `total timesteps` 那行就是证据）。

### 2.5 结果判读：怎么算「学会了」

Pendulum 每步奖励的理论上限是 **3.10**（`3.0·upright + 0.1`，竖直静止时），
所以直接看「累计奖励 ÷ 步数」：

| 平均每步奖励 | 含义 |
| --- | --- |
| ≈ 3.10 | 全程稳定直立，学到位了 |
| 1.0 左右 | 垂在下面不动（只拿到能量项的 1.0） |
| 0 附近或为负 | 没学出来，乱摆 |

用脚本一行看：

```bash
python3 scripts/23_analyze_episode.py --env pendulum --csv evidence/week4/csv/pendulum_demo_seed0.csv
# 看「末帧°」「直立占比」「累计奖励」三列
```

> **视频只有两三百 KB 是正常的**：摆杆稳定直立时画面几乎不动，x264 会把静止场景压得很小。
> 文件小 ≠ 录坏了，用 `ffprobe` 确认时长对（约 7–10 s）即可。

**seed 与初始姿态的对应**（`np.random.seed(seed)` 后第一次 `uniform(-π,π)` 抽样）：

| seed | 初始角度 | 画面效果 |
| --- | --- | --- |
| 0 | +17.6° | 几乎一开始就竖直，**看不出摆起过程** |
| 1 | −29.9° | 小幅修正 |
| 2 | −23.0° | 小幅修正 |
| **4** | **+168.1°** | **接近垂下，能看到完整摆起过程（推荐录 demo 用）** |
| **6** | **+170.2°** | 同上 |

所以想要一个"看得出效果"的 demo 视频，额外录一条：

```bash
ENV=pendulum TAG=demo SEED=4 bash scripts/21_record_episode.sh
```

> A/B 实验仍按作业要求用 seed 0/1/2（这 3 个起点都接近竖直，
> 两组都容易进入直立范围，差异会体现在"进入时刻"和"末帧"上；
> 想更有区分度可以额外补 seed 4/6，作为补充证据单独标注）。

## 6. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `play.py` 报 `No DISPLAY` | 在 KDE 桌面终端里跑，或 `export DISPLAY=:20` |
| 视频全黑 | 仿真窗口被其他窗口挡住 → 最小化其它窗口后重录 |
| 视频太短/太长 | `STEPS` 与环境不匹配：cartpole 1000、pendulum 400、acrobot 500 |
| `best_agent.pt` 不存在 | 训练被中断，用 `checkpoints/agent_*.pt` 里时间戳最大的那个 |
| `23_analyze_episode.py` 说找不到文件 | 路径要相对仓库根目录；先 `ls evidence/week4/csv/` |
| A/B 两组初始姿态不一致 | 回放漏了 `--seed`；`21_record_episode.sh` 已默认带 seed |
| 训练完 `git status` 显示 pendulum_np.py 被改 | 说明 B 组代码没恢复，跑 `bash scripts/22_pendulum_ab.sh` 的 train 阶段会自动 revert |
